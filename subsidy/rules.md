# rules.md — правила разработки (кейс «Субсидии»)

> Каждое правило защищает от снятия с конкурса или от потери баллов. В скобках — ссылки на критерии положения (Д = допуск, СН = снятие, Б = бонус).

## 1. Красные линии (нарушение = снятие)
1. **Вид документа — только по содержимому** (Д9, СН). Тип определяет модель по тексту/изображению страницы. Имя файла, расширение, порядок файлов в архиве и «в какое поле положили» в классификатор не передаются (`guard.sh` ловит `originalFilename`/`getName()` в docproc/ocr). Один PDF может содержать несколько документов — делим по содержимому страниц.
2. **Проверка документов и правил — на сервере** (Д2, Д11, СН). Комплектность, правила, сроки и **вся арифметика** (суммы, НДС, ставка, лимит субсидии) считаются в `rules` на `BigDecimal`. Фронт только показывает результат; ни одного `sum`/`reduce`/сравнения дат для вердикта в `frontend/` (`guard.sh` ищет).
3. **Разбор только моделью, правила — кодом** (Д5, СН). Тип и поля извлекает модель через `LlmGateway`; детерминированный код нормализует и проверяет (контрольные суммы ИНН/ОГРН/БИК/счёта, даты, суммы). Регулярки и шаблоны не заменяют модель как основной путь.
4. **Никакой подгонки под тестовые файлы** (СН). Нельзя: имена/хэши/ИНН из открытого набора в коде и промптах, правила «если ООО Ромашка», few-shot из открытого набора. Можно: синтетика (`eval/synthetic/`), общие признаки видов из `docs/DOC-TYPES.md`. Открытый набор — вне git, только для замера (`docs/EVAL.md`).
5. **Никаких заготовленных результатов** (СН). Протокол — только из реального разбора и реального прогона правил. Модель недоступна → `WAITING_MODEL` и автоповтор, а не «пакет проверен». Пустое поле ≠ «проверка пройдена»: правило без данных → `NOT_APPLICABLE`/`DATA_MISSING` с причиной.
6. **Приём мгновенный, разбор в фоне, работа не теряется** (Д4). `POST` файла/архива → `202` со статусом `RECEIVED`; разбор — очередь `jobs` в PostgreSQL (lease + `FOR UPDATE SKIP LOCKED`), стадии в БД; рестарт посреди разбора → продолжение.
7. **Только PostgreSQL** (Д4, СН). Файлы — `bytea` AES-256-GCM, Keycloak — в PostgreSQL. Никаких `Map`-хранилищ, H2/SQLite, файлов на диске, «только в Kafka».
8. **Данные организаций — только после входа**. Каждый эндпоинт и файл проверяют JWT и роль на сервере; прямая ссылка без входа → 401; чужой пакет → 404.
9. **Модель — только через `LlmGateway` в `libs/llm`** (Д6). SDK и URL провайдеров — только там (ArchUnit + `guard.sh`). Провайдер — `LLM_PROVIDER`; локальный Ollama работает без интернета.
10. **Никаких секретов в git** (Д7, СН). Только `infra/.env` (в `.gitignore`), в репо — `.env.example`. Реальные документы организаций и открытый набор в git не кладём.
11. **Каждый понимает свой код** (Д12, СН). Не мержим код, который владелец не объяснит за 60 секунд.
12. **Без вирусных лицензий** (п. 5.8.4). Запрещены GPL/AGPL/SSPL: PyMuPDF/fitz, pdf2image + poppler, ghostscript, iText, MinIO, Camelot с ghostscript. PDF — `pypdfium2` + `pdfplumber`, OCR — Tesseract, выгрузки — Apache POI / PDFBox. Новая зависимость = строка в `docs/DECISIONS.md` с лицензией. Веса моделей — только с разрешающей лицензией.
13. **Код пишется только на хакатоне** (п. 7.3). До старта — документы, правила, скрипты, CI.

## 2. Архитектура (как в «Проходной», ADR-001)
- Сервисы в `services/<name>/`, общие библиотеки `libs/common` (инфраструктура) и `libs/llm` (слой модели). Бизнес-логики в libs нет.
- `package` владеет организациями, пакетами и файлами; `docproc` — заданиями, типами и полями; `rules` — комплектностью, правилами, протоколами, историей и статистикой; `assistant` — вопросами по пакету. Чужую БД не читаем: `/internal/**` или события.
- События — только через outbox, потребители идемпотентны по `eventId`, топик `<владелец>.<агрегат>.v<N>`.
- Деньги — `BigDecimal` (`numeric(19,2)` в БД, `HALF_UP` только в одном месте — `Money`), даты — `LocalDate`, время — через `Clock`. Никаких `double` для сумм.

## 3. Backend-конвенции (Java, Python)
- Полные правила — скилл `../.agents/skills/backend-spring/SKILL.md`. Java 21, Spring Boot 3.5, Gradle Kotlin DSL, версии только в `services/gradle/libs.versions.toml`.
- Пакеты `ru.subsidy.<svc>`: `api/controller` (+`impl`), `api/dto/request/*Rq`, `api/dto/response/*Rs`, `features/<f>/…`. ArchUnit + `be-check.mjs`.
- jOOQ + Liquibase, миграции только `scripts/new-migration.sh <svc> <slug>`. Смерженный changeset не редактируем.
- Ошибки — RFC 7807 `application/problem+json` с `code` из API.md, `detail` по-русски и `hint`.
- Обязательные тесты: проверки приёма, очередь (рестарт, гонка), **каждое правило — тест с числами** (граница, копейки, НДС), контрольные суммы ИНН/ОГРН/КПП/БИК/р/с, классификатор не видит имя файла (тест с переименованными файлами), матрица «эндпоинт × роль» + IDOR, прогон `eval/` в CI на синтетике.
- Python (ocr): `uv`, `ruff`, `mypy --strict`, `pytest`; FastAPI, pydantic; ошибки — problem+json.
- Логи в JSON с `traceId`. Тексты документов и реквизиты в логи не пишем — только id и коды.

## 4. Frontend-конвенции
- Полные правила — скилл `../.agents/skills/frontend-fsd/SKILL.md`; дизайн — `frontend/docs/DESIGN.md` (токены общие с «Проходной»).
- Одно приложение Vite + React 19 + TS strict, FSD, зона `/specialist` (desktop, роли через Keycloak).
- Типы API — из `contracts/openapi/*.json` (`npm run gen:api`). Ручной `fetch` запрещён. Токены — в памяти.
- Каждый экран: загрузка, пусто, ошибка («Повторить»), данные, нет сети. Статусы файлов — без перезагрузки (SSE).
- Вердикты, суммы и «не хватает» — **только из ответа сервера**; клиент их не вычисляет.

## 5. Git
- Trunk-based: короткие ветки `feat/RUL-02-arithmetic`, мерж в `main` только через PR по зелёному CI. Conventional Commits со ссылкой на ID: `feat(rules): FR-31 проверка суммы субсидии`.
- Коммитит автор под своим именем (история — часть оценки, Д7).
- Никаких `node_modules`, `build/`, `.venv/`, `.env`, моделей, сканов и документов организаций в git.
- Каждые 2 часа — тег `subs-demo-N`.

## 5.1 Работа через PR
Цикл и скрипты — скилл `subsidy-dev`: ID → ветка → `scripts/verify.sh` + `scripts/guard.sh` → `scripts/open-pr.sh`. Автор не апрувит свои PR. Мерж — владелец модуля после зелёного CI и ревью. После clone: `scripts/install-hooks.sh`.

## 6. Definition of Done
- [ ] Требование FR/NFR закрыто, ID в коммите
- [ ] Работает через интерфейс специалиста, а не только через curl
- [ ] Ошибки и замечания внятные, коды из API.md / RULES-CATALOG.md
- [ ] Состояние в БД, переживает рестарт; разбор — в фоне
- [ ] Тест или шаг в `scripts/smoke.sh`; для типа/полей — `eval/` не хуже, чем было
- [ ] Владелец может объяснить код
- [ ] Документация/ADR обновлены
