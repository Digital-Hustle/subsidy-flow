# PRD — frontend «Субсидий»

Общий продукт — `../../docs/PRD.md`, требования — `../../docs/REQUIREMENTS.md` (G0, FR-60…68). Здесь — только интерфейс.

## Обзор
Одна зона `/specialist` (десктоп, вход через Keycloak): очередь пакетов → пакет (файлы, документы, оригинал рядом с результатом, протокол) → организация (история) → статистика. Судьи проверяют руками, UI — это и есть продукт (10 баллов + бонусы).

## Проблемы
- Специалист тонет в файлах — нужно сразу видеть: что за документы, чего не хватает, где ошибки.
- Ошибку нужно доказать: показать место на странице и формулу с числами.
- Неверно определённый тип или ошибка OCR должны исправляться в два клика с перепроверкой на сервере.

## Цели
1. Пакет понятен за 30 секунд: сверху статус и «не хватает», ниже ошибки → предупреждения → ок.
2. Оригинал рядом с результатом: клик по полю/ошибке → страница и подсветка (С13).
3. Смена типа, правка поля, дозагрузка → протокол обновляется без перезагрузки (С14–С15).
4. Каждый экран: loading / empty / error / offline; ни одного мока в prod; пустая БД → нули.

## Пользователи
| Кто | Что важно |
|---|---|
| SPECIALIST | очередь, пакет, протокол, правки, выгрузка |
| SENIOR_SPECIALIST | + решение, переразбор, программы, статистика |
| AUDITOR | протоколы, история, статистика, без правок и оригиналов |

## Ключевые функции
- **Пакет (F1):** создание (ИНН + программа), dropzone для файлов и ZIP, отказы приёма у файла, список файлов → документы (склейка раскрывается в несколько), вид + уверенность + стадия по SSE, сортировка «сомнительные сверху» (B-08); `DocumentViewer` + `FieldsPanel`; смена типа, правка поля, замена файла, удаление.
- **Протокол и аналитика (F2):** очередь пакетов (фильтры в URL); `ProtocolPanel` (комплектность, правила с ожидаемым/фактическим, ссылки на документ), версии протокола; выгрузка (B-02); «чего не хватает» с текстом запроса (B-07); организация и история (B-03); статистика ошибок (B-04); истекающие (B-05); помощник (B-06); бейдж модели.
