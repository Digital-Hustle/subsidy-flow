# F1 — заявка и документы

Все F1-1…4 поставляются одной веткой `codex/f1-application-documents` и одним PR. Бэкенд и бизнес-проверки не меняются.

## Поведение

- `/operator`: «Новая заявка»; карточка — «Редактировать» для специалиста/старшего до решения. Общие поля используются также в анкете заявителя. Программа редактируемой заявки показана только для чтения: API не поддерживает её изменение.
- Программа и ИНН обязательны; остальные поля допускают пустое значение. Участок показывается для BEACH/MODERNIZATION, скрытые значения сохраняются в черновике, для остальных программ `property: null`.
- Сохранение: POST `/packages` с устойчивым Idempotency-Key, PUT `/packages/{id}/application` с expectedRevision, затем сверка GET. Ошибка сохраняет введённые данные; при частичном сохранении есть ссылка на созданную заявку. Конфликт ревизий требует открыть свежую карточку, перезаписывать чужие изменения автоматически нельзя.
- Форматы из исходного кейса: PDF, DOC/DOCX, XLS/XLSX, JPG/JPEG/PNG. Клиент помогает выбрать формат, сервер проверяет байты. ZIP/TIFF/HEIC не перечислены в кейсе. Смешанный набор загружает допустимые файлы; отказы показывают имя, причину и hint. Отказ замены не становится успехом.
- Извлечение отделено от введённой анкеты: beneficiary и guarantor раздельно, правообладатель и арендатор, подпись/печать/ЭП — обнаружено / не обнаружено / не определено. Подтверждение, страница, уверенность и проверки показываются при наличии. ЭП берётся из структуры файла и не означает криптографическую проверку.
- Файл без документов доступен как карточка файла. UNREADABLE/FAILED — завершившаяся проблема, WAITING_MODEL — ожидание модели. Ошибка превью сохраняет доступ к оригиналу, замене и дозагрузке. Повтор обработки — только старшему специалисту. Аудитор не получает действия записи и скачивание оригинала.
- Замена обновляет карточку и протоколы; fileVersion исключает устаревшее извлечение. Версия входит в URL и ключ кеша превью, оригинал скачивается авторизованным API, blob URL освобождается при смене/закрытии.

## Проверки

Из `subsidy/frontend`:

```sh
npm ci
npm test
npm run gen:api
npm run gen:tokens -- --check
npm run lint
npm run typecheck
npm run build
npm run fsd-check
```

14 unit-тестов проверяют черновик участка, пустые значения, деньги как строки, привязку ошибок, сверку сохранения и очистки, допустимые форматы, стороны, nullable признаки и старые версии извлечения. Все команды прошли. FSD: 2 существующих предупреждения в shared/ui/Input и Logo, нарушений нет.

Браузерный smoke — отдельный сценарий `tests/browser-smoke.cjs`. Требуется доступный Playwright и запущенный Vite; тест перехватывает API синтетическими ответами только внутри браузерного контекста, продукционный код не содержит фикстур. Новые зависимости в приложение не добавлены.

```sh
FRONTEND_URL=http://127.0.0.1:5173 \
PLAYWRIGHT_MODULE=/absolute/path/to/playwright \
CHROME_PATH=/absolute/path/to/chrome \
PW_TEST_SCREENSHOT_NO_FONTS_READY=1 node tests/browser-smoke.cjs
```

Проверены Chrome, 1440×900 (светлая тема), 390×844 (тёмная тема и форма): создание и переключение программы с сохранением участка, управление селектом клавиатурой, ошибка редактирования и повтор с прежней ревизией, смешанные форматы выбором и DnD, частичный серверный отказ, отказ/успех замены, новая версия превью без старых полей, файл без документов, авторизованный оригинал, повтор обработки, SSE-переходы WAITING_MODEL/FAILED, HTTP 503 превью и восстановление, роли и принятое решение. Горизонтального переполнения и ошибок выполнения нет. Скриншоты `/tmp/f1-*.png`; внешние шрифты заблокированы в тесте, проверка загрузки CDN не входит в smoke.

Ручная приёмка на реальном API: создать минимальную заявку, затем заполненную, проверить ошибки у полей и повтор после исправления; отредактировать с ожидаемой ревизией. Загрузить смешанный набор, заменить отказанным и корректным файлом. Для UNREADABLE/FAILED открыть оригинал и повторить обработку старшим; проверить новые результаты по SSE. Повторить под специалистом/аудитором и для DECIDED.

## Фактические ограничения интеграции

На 2026-10-10 сверены `feat/B1-application-pdf-intake` (2eb53c5) и `feat/DP-17-extract-schemas` (ebcf9fd). Эти ветки не подмешиваются в PR фронтенда.

- B1 пока проверяет только PDF. Остальные форматы доступны по требованиям кейса, но до расширения backend будут отклоняться с причиной сервера.
- B1 требует полную анкету (включая реквизиты ООО), тогда как F1 допускает частичное заполнение и ИП. Минимальное создание использует старый контракт без application; заполненная анкета сохраняется только если сервер её принимает.
- B1 ещё не сохраняет totalCost/ownFunds/property.area/purpose/rightHolder. Фронтенд отправляет расширенную модель и сверяет прочитанные значения, чтобы не показать ложный успех при игнорировании полей.
- Подпись/печать: ожидаются nullable boolean `signaturePresent`/`stampPresent`, raw/confidence/page/checks; в текущей схеме DP-17 их пока нет. Отсутствие результата показывается как «Не определено». EP — `file.electronicSignature.present` и reason.
- Проверки интерфейса с фикстурами не заменяют сквозную проверку с развёрнутым B1/DP-17.

`subsidy/scripts/ci-local.sh quick` и `full` запущены: verify останавливается на `mapfile: command not found` (системный Bash 3.2 macOS). Guard прошёл с существующими permitAll-предупреждениями. Docker/Testcontainers и gitleaks недоступны локально. PR остаётся draft до полного зелёного CI; проверки не отключены.
