# PRD — package

Продукт целиком — `../../../docs/PRD.md`, требования с ID — `../../../docs/REQUIREMENTS.md`. Здесь — только этот модуль.

## Обзор
Всё, что касается входящих данных: организация по ИНН, пакет на программу, приём файлов и архивов с проверками, дубликаты, повторная загрузка и замена (версии), хранение в PostgreSQL зашифрованным, выдача оригиналов специалисту и docproc, SSE статусов пакета. Ответ мгновенный — разбор идёт в docproc (Д4).

## Проблемы
- Пакеты приходят архивами с мусором, вложенными архивами, битыми и запароленными PDF.
- Имя файла и порядок не должны влиять на тип (СН) — package не передаёт их дальше.
- Файлы — коммерческие и банковские данные: только в БД и зашифрованно.

## Цели
1. Каждый отказ — код + текст + подсказка, ни одного 500 на «плохой» файл.
2. `202` p95 ≤ 300 мс: файл + запись + outbox одной транзакцией.
3. Замена файла → новая версия → переразбор и перепроверка (С15).
4. Данные переживают рестарт (Д4).

## Пользователи
- Специалист — через `/specialist`.
- docproc — `/internal/package/files/{id}`.
- rules — события пакета.

## Ключевые функции
- Организации (ИНН с контрольной суммой), пакеты (программа, статус).
- Проверки: пустой, размер, сигнатура (Tika), целостность (PDFBox/ImageIO/POI), пароль PDF, страницы, разрешение; sha256-дубликаты.
- ZIP: Commons Compress, лимиты распаковки и записей, без вложенных архивов и опасных путей; каждый файл — запись `files`.
- Версии файлов, удаление, решение по пакету (SENIOR).
- Хранение `content_enc` AES-256-GCM; превью страниц через ocr (кэш в БД).
- SSE пакета из событий docproc и rules.
