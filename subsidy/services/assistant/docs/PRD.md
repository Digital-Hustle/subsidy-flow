# PRD — assistant

Продукт целиком — `../../../docs/PRD.md`, требования с ID — `../../../docs/REQUIREMENTS.md`. Здесь — только этот модуль.

## Обзор
Специалист спрашивает «почему не прошла сумма субсидии?», «какие документы просрочены?», «что необычного в пакете?». Модель через `LlmGateway.chat` выбирает инструменты чтения (протокол, поля, аномалии), отвечает только по их результатам, со ссылками на документы; валидатор сверяет каждое число в ответе с данными инструментов.

## Проблемы
- Модель может выдумать числа — нужен валидатор.
- Помощник не должен влиять на протокол и доступ.

## Цели
1. Каждое число ответа найдено в результатах инструментов, иначе пометка `NUMBERS_MISMATCH`.
2. Ответ со ссылками на документ/поле/правило.
3. Права — те же, что у специалиста на пакет.

## Пользователи
- Специалист, старший специалист.

## Ключевые функции
- `POST /packages/{id}/ask` → ответ, источники, таблица, статус валидатора.
- Инструменты: `get_protocol`, `get_fields(type?)`, `find_anomalies`, `get_missing` — через `/internal/rules/packages/{id}/facts`.
- История диалога в БД.

## MVP
| Обязательно (P0, к интеграции №1–2) | Потом (P1/P2, если есть время) |
|---|---|
| вопрос → инструменты → ответ с источниками + валидатор | история диалогов, подсказки вопросов |
