# PRD — docproc

Продукт целиком — `../../../docs/PRD.md`, требования с ID — `../../../docs/REQUIREMENTS.md`. Здесь — только этот модуль.

## Обзор
Фоновый конвейер: из `FileReceived` — задание; воркеры по стадиям получают текст (ocr; DOCX/XLSX — POI), делят файл на документы и определяют вид каждого моделью по содержимому, извлекают поля по JSON Schema вида, нормализуют суммы и реквизиты, считают уверенность и публикуют результат для rules. Ручная смена типа → переизвлечение.

## Проблемы
- Тип по имени/порядку/расширению = снятие; файлы названы бессмысленно и склеены.
- Суммы и реквизиты на сканах читаются с ошибками — нужна нормализация и проверка.
- Модель медленная и падает — работа не должна теряться.

## Цели
1. Accuracy и macro-F1 типа на открытом наборе — в отчёте eval каждого PR про промпты/предобработку.
2. Склейка из N документов → N документов с верными типами.
3. Рестарт посреди разбора → продолжение с сохранённой стадии.
4. Деньги — `BigDecimal` до копейки, реквизиты — с контрольными суммами.

## Пользователи
- rules — поля для комплектности и правил.
- package — стадии для SSE.
- Специалист — смена типа, переразбор.

## Ключевые функции
- Очередь `jobs` (SKIP LOCKED + lease), `stage_events`, `stage_outputs`.
- Сегментация + классификация (`segment.v1`, `classify.v1`), `TYPE_UNKNOWN`, `OTHER`.
- Извлечение по `doc_types.schema`, таблицы позиций.
- Нормализация: суммы (пробелы, запятые, «руб.»), даты, ИНН/ОГРН/КПП/БИК/р/с.
- Уверенность типа и полей, порог → NEEDS_REVIEW.
- `PUT /documents/{id}/type` → переизвлечение, история результатов.
- Журнал `llm_calls`, `/model/status`.
