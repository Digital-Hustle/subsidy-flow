# PRD — rules

Продукт целиком — `../../../docs/PRD.md`, требования с ID — `../../../docs/REQUIREMENTS.md`. Здесь — только этот модуль.

## Обзор
Детерминированный движок: по определённым видам и извлечённым полям проверяет комплектность по чек-листу программы (с условиями), реквизиты и их совпадение между документами, сроки, арифметику сумм на `BigDecimal`, аномалии; формирует неизменяемый протокол с объяснениями и ссылками на места в документах; принимает правки полей специалистом и перепроверяет; выгружает протокол; ведёт историю по организации и статистику ошибок.

## Проблемы
- Правила на клиенте = снятие (Д11); арифметика с `double` даёт копеечные ошибки.
- Специалисту нужно доказательство: какое поле, где на странице, что ожидалось.
- Чек-лист и параметры меняются по программам — не код.

## Цели
1. Каждое правило — тест с числами (граница, копейки, НДС) до кода.
2. Протокол объясним и воспроизводим (версии чек-листа, правил, входных данных).
3. Правка поля → новая версия протокола ≤ 2 с.
4. Пустые данные → `DATA_MISSING`, а не PASSED.

## Пользователи
- Специалист (протокол, правки), старший (программы, статистика), аудитор (чтение).

## Ключевые функции
- `programs` и `checklists` — данные с версиями; демо-программа — контекст `demo`.
- Проекция пакета из событий docproc (`package_view`).
- `CompletenessEngine`: обязательные, условные, «один из», дубликаты, неизвестные.
- `RuleEngine` + `Rule`-классы из RULES-CATALOG (`REQ_*`, `CROSS_*`, `DATE_*`, `SUM_*`, `ANOMALY_*`).
- `Money` (BigDecimal, scale 2, HALF_UP, допуск 0.01).
- Протокол-снимок, версии, экспорт DOCX/XLSX/PDF (POI/PDFBox).
- `org_history` append-only, статистика по `rule_results`, истекающие документы.
