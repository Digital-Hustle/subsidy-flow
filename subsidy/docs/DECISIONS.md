# Журнал решений (ADR-lite) — «Субсидии»

Формат: `ADR-NNN | контекст | решение | альтернативы | последствия`. Унаследованные от «Проходной» — `← P-ADR-NNN`, от «Документов» — `← D-ADR-NNN`. Новое значимое решение (технология, формат, отказ от функции, лицензия) — новая запись в конец.

### ADR-001 Микросервисы как в «Проходной» ← P-ADR-015, 017, 024
Решение: gateway + package, docproc, ocr (Python), rules, assistant; БД и роль на сервис в одном PostgreSQL; Kafka + outbox. Альтернатива: монолит — проще, но теряем подготовленный процесс и скиллы. Срез scope: assistant вливается в rules, если не успеваем.

### ADR-002 Очередь разбора — таблица `jobs` в PostgreSQL ← D-ADR-002
Kafka доставляет «файл принят», воркеры берут `FOR UPDATE SKIP LOCKED` с lease, стадии и промежуточные результаты в БД. Закрывает Д4 и СН «данные в памяти».

### ADR-003 OCR — отдельный Python-сервис ← D-ADR-003
`pdfplumber` (текст и таблицы), `pypdfium2` (рендер), OpenCV, Tesseract `rus+eng`; DOCX/XLSX — Apache POI в docproc. Решения — в Java.

### ADR-004 Модель за `LlmGateway` в `libs/llm`, локально Ollama ← P-ADR-005, D-ADR-004
Библиотека в docproc и assistant; `qwen3:8b` (текст) + `qwen2.5vl:7b` (vision), Apache-2.0; выбор подтверждается замером (LLM.md).

### ADR-005 Тип — по содержимому, с сегментацией многодокументных файлов
Контекст: 25 баллов и СН «тип по имени/порядку/расширению». Решение: в событие для docproc не передаются имя, путь в архиве и порядок; модель получает страницы и реестр видов, возвращает сегменты `[страницы → вид, уверенность, обоснование]`; код проверяет покрытие страниц. Альтернатива: «один файл = один документ» — проваливает склеенные сканы. Последствия: тест «переименовали и перемешали — те же типы», `guard.sh`.

### ADR-006 Модель извлекает, правила — детерминированный код
Модель только читает (тип и поля); комплектность, реквизиты, даты, арифметика — Java-код в `rules` с тестами на числа (Д11). Параметры программы (ставка, лимит, сроки, ОКВЭД) — данные `programs` с версией. Альтернатива: «спросить модель, всё ли в порядке» — недетерминированно и необъяснимо.

### ADR-007 Деньги — `BigDecimal`, в JSON строками
`numeric(19,2)`, `RoundingMode.HALF_UP` только в `Money`, допуск сравнения 0.01; в API деньги — строки. Альтернатива: `double` — копеечные ошибки в правилах.

### ADR-008 Протокол — неизменяемый снимок с версиями
Каждая перепроверка создаёт новую версию `protocols` (снимок входных данных, версии чек-листа, правил, промптов). Экспорт и история строятся из снимков → воспроизводимо и объяснимо.

### ADR-009 Правки специалиста — данные поверх результата модели
`field_overrides` и смена типа хранятся отдельно от результата модели (`source=SPECIALIST`), правила пересчитывает сервер. Фронт никогда не присылает статусы правил.

### ADR-010 Файлы в PostgreSQL, AES-256-GCM ← P-ADR-009, D-ADR-007
`bytea` до 30 МБ, ключ из `.env`, nonce на версию файла. MinIO — AGPL.

### ADR-011 ZIP — распаковка на сервере с лимитами
Лимиты размера, числа записей, без вложенных архивов, без `..`/абсолютных путей; каждый файл — отдельная запись `files`; имя файла хранится только для отображения.

### ADR-014 Помощник — инструменты + валидатор чисел (как assistant «Проходной»)
Модель выбирает инструменты чтения (`get_protocol`, `get_fields`, `find_anomalies`), ответ только по их результатам, числа сверяет валидатор; расхождение — пометка в ответе. Помощник ничего не меняет.

### ADR-015 Процесс: draft PR, локальный CI, мерж владельцем ← P-ADR-014, 034, 035
Одна задача — одна ветка и один PR; проверки локально (`scripts/ci-local.sh`) те же, что в CI; мерж — владелец модуля после зелёного CI и ревью (`WORKFLOW.md`).

### ADR-016 Превью страниц рендерит package (PDFBox / ImageIO), кэш в `page_previews`
Превью работает без ocr: не нужен сетевой хоп и передача расшифрованного файла. ocr `/v1/render` остаётся для тяжёлых сканов. PDFBox — Apache-2.0, в разрешённом списке.

### ADR-017 CI — на сервере команды, статус `server-ci` на коммит
GitHub Actions не стартуют (биллинг аккаунта), поэтому те же шаги (`guard`, gitleaks, jOOQ на своей БД, `check` по изменённым сервисам, `exportOpenApi`, ocr/eval/frontend/infra) гоняет скрипт на сервере под общим lock и ставит commit status `server-ci`. Мерж — только при зелёном `server-ci`; красные `changes`/`security` из Actions — не по коду.

### ADR-018 Проекция rules сверяется с docproc (RUL-18)
События at-least-once, но потеря/порча события не должна давать неполный протокол. Перед расчётом протокола rules проверяет: если у разобранного файла в проекции нет документов — тянет `/internal/docproc/packages/{id}/documents` (svc-rules) и сверяет. Ручной вызов — `POST /projection/rebuild` для SENIOR. Источник правды о разборе — docproc, rules хранит только проекцию.

### ADR-019 Выброс статьи сметы — mean + 3σ по программе, не медиана (RUL-17)
Медиану в PostgreSQL по JSON-полям считать дорого и неинкрементально; `avg`/`stddev_pop` — одним агрегатом. Правило — WARNING (аномалия, не отказ), не применяется при < 20 пакетах программы: на малой выборке σ бессмысленна.

### ADR-020 Rate-limit в gateway — в памяти, окно в минуту на пользователя (GW-05)
Один инстанс gateway, Redis ради счётчиков не тащим (лишний сервис и лицензия). При рестарте счётчики обнуляются — допустимо. Ключ — `sub` JWT, лимиты в env. Размер тела режется по `Content-Length` до сервисов (413), лимит на файл остаётся в package (`FILE_TOO_LARGE`).

### ADR-021 Слабый OCR → модель видит и картинку (DP-14)
Страница скана со средней уверенностью Tesseract ниже `VISION_OCR_MIN_CONF` помечается `OCR_WEAK`: текст остаётся, но при `VISION_FALLBACK_ENABLED` модель получает и изображение. Текстовый слой PDF не трогаем. Порог подбирается замером на открытом наборе.

### ADR-022 Вход на странице: форма Keycloak во фрейме того же origin (FE-UI-02) — заменён ADR-023
Форма входа — страница Keycloak (тема `infra/keycloak/themes/subsidy`) во фрейме внутри карточки фронта: пароль и код TOTP вводятся только в Keycloak, фронт их не видит. Запрос и PKCE — как у редиректа; callback во фрейме передаёт адрес родителю (`postMessage` с проверкой origin), токены — в памяти вкладки. После перезагрузки — тихий вход `prompt=none` по cookie сессии Keycloak. Для фрейма Caddy отдаёт `X-Frame-Options SAMEORIGIN` вместо `DENY`. Своя форма логина с паролем (ROPC) отвергнута: устаревший поток, ломает TOTP и brute-force защиту.

### ADR-023 Вход сотрудников по коду из письма, два издателя токенов, режим стенда (FE-UI-04)
Сотрудник входит по рабочей почте: `POST /package/api/v1/auth/code` → 6-значный код письмом, `verify` → access-токен в памяти вкладки и refresh в httpOnly-cookie `subsidy_session` (`SameSite=Strict`, путь `/package/api/v1/auth`, ротация при каждом обновлении). Сессии сотрудников выпускает `package` (ES256, `STAFF_TOKEN_SIGNING_KEY`, JWKS `/internal/staff/jwks`), Keycloak остаётся издателем только для межсервисных `svc-*`. Сервисы принимают оба издателя: декодер выбирается по `iss` (`IssuerJwtDecoder` в `libs/common`), токен сотрудника с `azp` отвергается. Keycloak во фрейме (ADR-022) больше не используется для сотрудников: пароль и TOTP не нужны, почта и так второй фактор, а форма входа одинакова во всех трёх кейсах.
Коды хранятся только в виде хэша с солью `STAFF_CODE_PEPPER`, живут `STAFF_CODE_MINUTES`, 5 попыток, повторная отправка не чаще `STAFF_RESEND_SECONDS`; на gateway — лимит `RATE_LOGINS_PER_MINUTE` по IP. Войти может только заведённый сотрудник (`STAFF_BOOTSTRAP_EMAIL` — первый старший; дальше приглашения в «Сотрудниках»); у неизвестной почты ответ такой же, чтобы не раскрывать список.
`STAND_MODE` переключает стенд: `demo` — демо-сотрудники, код `000000` и код в ответе API (видно на странице входа, как в песочнице); `prod` — демо-сотрудники отключаются при старте, код только письмом. Почта — общий ящик всех кейсов (корневой `MAIL.md`, `infra/mail.env`); без SMTP письмо не уходит, вход остаётся рабочим только в демо-режиме.

### ADR-024 Виды документов и правила — по тексту кейса, правила хранятся данными программы (FR-30)
Перечень видов — 9 документов из кейса 3 (заявление, согласие на ПД, сертификат соответствия, презентация, обоснование затрат, выписка из банка, документ на недвижимость, гарантийное письмо, декларация ГИМС) и «прочее»; гипотезы прошлой версии (ЕГРЮЛ, справка ФНС, счёт, платёжка, бухотчётность) убраны. Комплект и условные документы — `programs.params.required/conditional`, правила п. 4.3 — `programs.params.rules`: список `{code, op, title, severity, params}` над небольшим набором операций (`REQUIRED_FIELDS`, `PATTERN`, `DATE_NOT_FUTURE`, `NOT_EXPIRED`, `SAME_VALUE`, `RATIO_MIN`, `EQUAL_SUM`, `NOT_EMPTY`, `RANGE`), операнды — выражения `ВИД.поле` и разность двух полей. Администратор меняет пороги, документы и формулировки без правки кода; `ProgramService.update` отвергает неизвестную операцию или параметры (`VALIDATION_ERROR`). Альтернатива — DSL/скрипты (SpEL, JS): гибче, но небезопасно и не проверяется до запуска. Хардкод-правила оставлены только для статистики (выброс статьи, RUL-17).

### ADR-025 ИНН и ОГРН проверяются по формату, не по контрольной сумме
В открытом наборе реквизиты синтетические: контрольная сумма может не сходиться, и это не признак ошибки заявителя. Docproc отмечает только `FORMAT_INVALID` (10/12 цифр ИНН, 13/15 ОГРН), правило `INN_SAME` сверяет ИНН между документами. Вернуть контрольную сумму — параметр операции `PATTERN` в программе, без релиза.
