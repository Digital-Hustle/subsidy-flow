# PRD — «Субсидии»: автоматическая проверка пакета документов

## Обзор
Специалист фонда/министерства получает от организации пакет из 10–40 файлов: сканы, PDF, архивы, файлы названы как попало, документы склеены в один PDF. Сейчас он вручную разбирает, что есть что, сверяет ИНН в каждой бумаге, пересчитывает суммы в смете и счетах, проверяет свежесть справок. Система делает эту работу за минуты и показывает специалисту только то, что требует решения человека.

## Проблемы
- Разбор пакета вручную — часы на пакет; ошибки в арифметике и реквизитах пропускаются.
- Документы приходят без структуры: имена файлов бессмысленны, порядок случаен, несколько документов в одном файле.
- Неполные пакеты обнаруживаются поздно; организация не знает, чего не хватает.
- Решения трудно объяснить и повторить: где именно расхождение, по какой версии правил.

## Цели
1. Вид каждого документа определяется по содержимому, включая склеенные файлы (25 баллов).
2. Комплектность по чек-листу программы с условиями — «чего не хватает и почему» (15).
3. Поля извлекаются моделью, правила и арифметика — на сервере, с объяснением и ссылкой на место в документе (20).
4. Модель меняется настройкой, локальный режим работает без интернета (15).
5. Рабочее место: оригинал рядом с результатом, смена типа, дозагрузка, закрытость (10).

## Пользователи
| Кто | Что важно |
|---|---|
| Специалист | быстро понять статус пакета, увидеть ошибки с доказательством, поправить тип/поле, дозагрузить, выгрузить протокол |
| Старший специалист | решение по пакету, переразбор, параметры программы, статистика ошибок |
| Аудитор | протоколы и история без права изменений |
| Организация-заявитель (косвенно) | получает понятный список недостающего и ошибок (выгрузка протокола) |

## Ключевые функции
- Пакет: организация по ИНН, программа, загрузка файлов и ZIP в любом порядке, серверные проверки, дубликаты, версии.
- Конвейер в фоне: текст → сегментация и вид → поля → контрольные суммы → комплектность → правила → протокол.
- Протокол: ошибки / предупреждения / ок, у каждой — объяснение, ожидаемое и фактическое значение, ссылка на документ, поле и место на странице.
- Бонусы: сверка реквизитов между документами, выгрузка протокола, история по организации, статистика частых ошибок, истекающие справки, помощник с аномалиями, «чего не хватает», уверенность типа по файлу.

## MVP
| Обязательно (P0) | Потом (P1/P2) |
|---|---|
| вход, пакет, загрузка с проверками, очередь jobs, тип по содержимому для 8 видов, поля, комплектность, арифметика и реквизиты на сервере, протокол на экране, оригинал рядом, смена типа, дозагрузка, локальная модель | сегментация склеек, сверка между документами, выгрузка протокола, история, статистика, истекающие, помощник, аномалии |

## Метрики успеха
Прогон DEMO.md без провалов; чек-лист I из REQUIREMENTS зелёный; отчёт eval по 8 видам; ни одного нарушения `guard.sh`.

## Вне scope
Подача пакета самой организацией (кабинет заявителя), электронная подпись, интеграции с ФНС/СМЭВ (проверки по реквизитам — только локальные формулы; «запрос в ЕГРЮЛ» — нет).
