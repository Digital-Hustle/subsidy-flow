## 0. Подготовка (до выхода)
- Стенд в `STAND_MODE=prod`: вход по коду из письма, сотрудники заведены старшим (страница «Сотрудники»). В БД — моковые пакеты вымышленных организаций по трём программам.
- Открытый набор организаторов — на сервере в `/root/openset/` (в git не кладём). Прогон: `python eval/run.py --api https://<host>` — отчёт по видам и полям.
- Вкладки: рабочее место, Jaeger, терминал с `docker compose`, отчёт eval.

## 1. Закрытость (С16) — 20 с
Открыть `/specialist` и прямую ссылку на файл без входа → вход / 401. Войти по коду из письма.

## 2. Пакет «как в жизни» (С1–С4, 25 баллов) — 90 с
Создать пакет программы «Инновационный проект», перетащить 6 PDF открытого набора (заявка, обоснование затрат, гарантийное письмо, презентация, выписка ЕГРН, справка из банка — скан). Имена файлов модели не передаются, порядок любой. Приём мгновенный, стадии вживую; скан справки читается OCR. Итог: каждый документ с видом и уверенностью; «Сомнительные сверху»; `J`/`K` — по документам.

## 3. Комплектность (С5–С7, 15) — 40 с
Протокол: «не хватает согласия на обработку персональных данных» (в наборе его нет), условный сертификат соответствия — предупреждение «дошлите также, если продукция подлежит сертификации». Отметить условие в пакете → сертификат стал обязательным. Сменить программу на «Обустройство пляжа» → комплект пересчитан (нужен документ на недвижимость, условно — декларация ГИМС).

## 4. Поля и правила п. 4.3 (С8–С11, 20) — 90 с
Открыть заявку: оригинал слева, поля справа, клик по полю → подсветка на странице. Правила: `OWN_FUNDS_SHARE` — «собственные средства 3 342 604,00 из 6 306 800,00 = 53 % ≥ 50 %»; `REQUEST_MATCH` — запрашиваемая сумма в заявке = обоснованию; `INN_SAME` — ИНН одинаков во всех документах; `DATE_NOT_FUTURE`, `NOT_EXPIRED`. Поправить поле (ошибка OCR) → сервер перепроверил, новая версия протокола. Администратор на странице «Программы» меняет порог 50 % → 60 % без релиза → протокол пересчитан (ADR-024).

## 5. Смена типа и повторная загрузка (С14–С15) — 30 с
Документ с низкой уверенностью → сменить тип → поля переизвлечены. Заменить размытый скан → разобран заново.

## 6. Устойчивость и модель (С18–С19, 15) — 60 с
`docker compose restart docproc` посреди разбора → продолжил с той же стадии (Jaeger). Если событие разбора потерялось, rules сам сверяет данные с docproc перед протоколом; вручную — кнопка «Сверить с разбором» (старший специалист). `docker compose stop ollama` → `WAITING_MODEL`, не «проверено»; `start` → догнал. Бейдж «Ollama · qwen3:8b». Показать `.env`: `LLM_PROVIDER=ollama` ↔ `openai`. Таблица замера моделей.

## 7. Бонусы (до +10, все 8 из Положения) — 60 с
Сверка между документами (`INN_SAME`, `REQUEST_MATCH`); выгрузка протокола DOCX для заявителя; история организации; статистика частых ошибок; истекающие сертификаты и декларации ГИМС; помощник: «почему не прошла доля собственных средств?» → ответ с источниками, сам подсвечивает аномалии; неполный пакет — «чего не хватает и как дослать» в протоколе; уверенность типа по каждому файлу и «Сомнительные сверху».

## 8. Инженерия — 30 с
Схема архитектуры, DECISIONS, CI зелёный, eval-отчёт по видам кейса (честно: где ошибаемся).
